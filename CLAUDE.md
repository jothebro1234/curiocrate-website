# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The marketing/donor website for CurioCrate, a STEM nonprofit (501(c)(3), est. 2023) that delivers free hands-on science kits to underserved communities. React SPA with heavy Framer Motion animation, deployed to **Cloudflare Pages** (curiocrate.org) — confirmed 2026-08-04 via the Cloudflare dashboard's Workers & Pages section. (An earlier version of this file incorrectly said Netlify; the `_headers`/`_redirects` config files use that same filename convention because Cloudflare Pages adopted it for Netlify-migration compatibility — don't take the presence of those filenames as evidence of which platform is actually hosting the site. Verify docs like this against reality before trusting them, this one was wrong for a while.)

## Commands

- `npm run dev` — start Vite dev server
- `npm run build` — production build to `dist/`
- `npm run lint` — ESLint
- `npm run preview` — serve the production build locally

No test suite exists in this repo.

## Architecture

**Stack:** React 19 + React Router 7 (`BrowserRouter`) + Vite 8 + Tailwind CSS 4 (via `@tailwindcss/vite`) + Framer Motion. `leaflet`/`react-leaflet` power the chapter map. Three.js/`@react-three/fiber`/`@react-three/drei`/`@react-three/postprocessing` + `gsap` (ScrollTrigger) power the cinematic 3D scroll experience on the Kits page (see below) — these were previously unused deps sitting in `package.json` before that page existed.

**Routing** is centralized in `src/App.jsx`: every route is listed there alongside the persistent `CinematicNavbar`, `CinematicFooter`, and `ParticleField` (ambient background) that wrap all pages.

**Legacy vs. active components:** `src/components/` contains both the active set (`CinematicNavbar.jsx`, `CinematicFooter.jsx`, used site-wide) and older unused duplicates left over from a previous design pass (`Navbar.jsx`, `Footer.jsx`, `BoardMembers.jsx`, `Mission.jsx`, the component-level `Gallery.jsx`). None of the legacy ones are imported by `App.jsx` or any page — check `App.jsx` and the relevant page file before assuming a component is live.

**Content is data-driven in two different ways:**
- Simple lists (impact stats, gallery photos, alumni, news, map pin locations) live in `src/data/*.js` and are imported directly by the components that render them.
- Team/board content (`src/pages/Team.jsx`) is hardcoded as arrays (`cabinet`, `directors`, `productOfficers`, `departmentHeads`) at the top of the file, each entry driving a shared `PanelStage` component (hover-to-expand card row). Per-member styling fields (`color`, `glow`, `dark`, `photoHeight`/`photoExpandedHeight`, optional `photoOffsetY`) control a card's theme color and how its cutout photo is sized/positioned — these needed hand-tuning to keep photos level across a row when photo source files have inconsistent framing/aspect ratios, so don't assume a uniform value works for a newly added photo.
- **Our Chapters** (`src/pages/OurChapters.jsx`) is the exception: it live-fetches from a Google Sheet via an Apps Script web app (`VITE_APPS_SCRIPT_URL` in `.env`; the GAS source is in `apps-script/Code.gs`). `src/data/chapters.js` is intentionally an empty array — it's a fallback shape, not real data, and isn't meant to be hand-edited.
  - **`apps-script/Code.gs` is shared with the Volunteer Portal** (a separate site) — it's the "Curio Crate Volunteer Portal" backend first and foremost (Curriculum/Events/Volunteers/Directors/DirectorRequests, timezone handling, gviz-safe instant columns, form-response sync, etc.), and the marketing site's `get_chapters`/`get_updates` endpoints are a small addition on top. When touching this file for a marketing-site reason, change only what's needed for that fix and leave the portal-related functions untouched — a careless edit here breaks volunteer-portal features for the other site, not just this one.
  - **Chapters sheet columns (A–R):** A=Email B=PresidentName C=School D=Logo E=State F=City G=PresidentPhoto H=VicePresident I=Treasurer J=Secretary K=SocialMedia L=AuthorizedDirectors M=Type N=Latitude O=Longitude P=Radius Q=Instagram R=PresidentMessage. `getChapters()` in `Code.gs` reads all of A–R and returns them under matching camelCase keys (`type`, `latitude`, `longitude`, `radius`, `instagram`, `presidentMessage`, etc.) — confirmed as of 2026-08-03 that the live sheet has all 18 columns filled in.
  - **Chapter vs. Impact rows:** `Type` (M) distinguishes real student-led high-school chapters (`Type="Chapter"`, or blank) from one-off teaching locations like YMCAs/elementary schools (`Type="Impact"`) — only `Chapter` rows should appear in the "Our Chapters" list/cards (`OurChapters.jsx`); `Impact` rows should show only as map markers, never in the chapter list. `getChapters()` normalizes column M case-insensitively (`/^impact$/i`) into a `type` field — the frontend filters (`c.type !== 'Impact'` in `OurChapters.jsx`, `c.type === 'Impact'` in `Home.jsx`) are case-sensitive string comparisons against that value, so if `getChapters()` ever stops returning `type` (as it did until 2026-08-03 — it silently omitted the field entirely, so every row's `type` was `undefined` and `undefined !== 'Impact'` meant Impact rows always leaked into the chapter list) or the normalization is removed, the bug comes back.
  - **Chapter map markers:** `Home.jsx`'s map prefers real `latitude`/`longitude` from the sheet (N/O) when present, falling back to a static `src/data/chapterLocations.js` lookup by school name for `Chapter`-type rows only — `Impact`-type rows have no such fallback, so an Impact row needs real N/O coordinates in the sheet to ever show up as a map marker. `radius` (P) sizes the impact-area circle in km, defaulting to 12.
  - **`apps-script/Code.gs` is shared with the Volunteer Portal** (a separate site) — it's the "Curio Crate Volunteer Portal" backend first and foremost (Curriculum/Events/Volunteers/Directors/DirectorRequests, timezone handling, gviz-safe instant columns, form-response sync, etc.), and the marketing site's `get_chapters`/`get_updates` endpoints are a small addition on top. When touching this file for a marketing-site reason, change only what's needed for that fix and leave the portal-related functions untouched — a careless edit here breaks volunteer-portal features for the other site, not just this one. **Always confirm the actual live script content with the user before editing it** — the version previously committed to this repo had drifted significantly from what was really deployed.
  - **After editing `Code.gs` you must redeploy** (Google Sheet → Extensions → Apps Script → Deploy → Manage deployments → pencil icon → Version: New version → Deploy) — saving the file alone does not update the live `/exec` URL that both sites call.

**Asset serving gotcha:** Several asset folders exist twice — once at the repo root (`boardmembers/`, `logos/`, loose image/video files) holding source originals, and once under `public/` (`public/boardmembers/`, `public/images/`, `public/logos/`, etc.) which is what Vite actually serves. Dropping a new file only at the repo root will 404 on the live site — it must also be copied into the matching `public/` subfolder.

**Deploy/caching (Cloudflare Pages):** The site is built and hosted directly on Cloudflare Pages (Cloudflare dashboard → Workers & Pages), connected to this GitHub repo for auto-deploy on push to `main` — there is no separate origin behind a CDN proxy; Cloudflare's edge cache and the Pages hosting are the same platform. `public/_headers` sets `index.html` to `no-cache` and `/assets/*` to `max-age=3600` (see below for why this isn't a long/immutable cache despite Vite content-hashing every JS/CSS filename). `public/_redirects` has the SPA fallback (`/* -> /index.html`) but explicitly carves out `/assets/*` first so missing assets 404 instead of being served the HTML shell.
- **Incident (2026-08-04):** users got "Failed to load module script... MIME type text/html" on a hashed `/assets/*.js` URL, persisting across hard refresh, incognito, disabled extensions, and a different network (cellular vs. home wifi) — that combination rules out anything client-side. Root cause: a request for a newly-deployed hashed asset URL landed in the brief propagation window right after a Cloudflare Pages deploy went live (before that file was fully available everywhere), got back the SPA-fallback HTML with a 200 status, and Cloudflare's edge cached *that* response under the `/assets/*` header rule — which at the time said `immutable, max-age=31536000` — regardless of the fact that the content didn't match what the URL was supposed to be. Once cached, no hard refresh or revalidation could fix it; it required a manual dashboard purge (Caching → Configuration → Purge Everything). **Caution:** testing a *freshly deployed* hashed URL yourself with `curl`/`WebFetch` within the first several seconds of a deploy can trigger this exact same poisoning (happened once, live, while diagnosing this very incident) — wait longer before checking, or be ready to purge again.
- **Fix (2026-08-04):** dropped `/assets/*` from `immutable, max-age=31536000` down to a plain `max-age=3600` (1 hour) in `public/_headers`. This means if the propagation-gap race ever poisons a cached response again, it self-corrects within an hour on its own — no purge, no webhook, no build plugin needed. The tradeoff is losing some of the performance benefit of caching content-hashed assets forever (a repeat visitor may occasionally re-fetch a file that, in principle, never changes) — a reasonable trade for a moderate-traffic nonprofit site given the alternative is a full year of being stuck broken. **Do not put `immutable` or a very long `max-age` back on `/assets/*` without also solving the propagation-race problem some other way** (e.g. a verified, working Cloudflare Pages "purge on deploy" mechanism) — reintroducing it reopens this exact incident.
- Two failure modes produce the same browser error message — diagnose before assuming it's the trivial one: (1) stale `index.html` in the visitor's own cache, fixed by a hard refresh (self-resolves since `index.html` is `no-cache`); (2) the edge-poisoning scenario above, NOT fixed by a hard refresh, and often geographically inconsistent (some regions/PoPs affected, others not) — a `curl`/`WebFetch` check from one location can look completely fine while other users still see it.
- If you ever need to force a brand-new asset URL on demand (e.g. to sidestep a cache issue immediately without waiting out the hour, or to force all clients onto a fresh bundle right away), bump the `window.__CURIOCRATE_BUILD__` marker string in `src/main.jsx` — it exists purely to force a new Vite content hash.
- **Do not assume Netlify.** An earlier version of this file incorrectly said the site was on Netlify, and real work (a `netlify.toml` + Netlify Build Plugin meant to auto-purge Cloudflare's cache after each deploy) was built and shipped against that wrong assumption before it was caught and removed — it would have silently never run, since there was no Netlify build pipeline to invoke it. `public/_headers`/`public/_redirects` are not proof of platform; Cloudflare Pages deliberately supports the same filenames for Netlify-migration compatibility. If deploy/hosting platform ever matters for a task, confirm it (e.g. ask the user to check their Cloudflare dashboard's Workers & Pages section, or check for platform-specific response headers) rather than trusting this file or file-format conventions alone.

**CSS:** `src/index.css` starts with the Google Fonts `@import` followed by `@import "tailwindcss"`. Per the CSS spec, `@import` rules must precede all other rules — reordering these (e.g. putting other CSS before the font import) has previously broken every custom font site-wide, silently.

**Kits page (`src/pages/Kits.jsx`) — cinematic 3D scroll experience:** This replaced an earlier "dev progress tracker" page. It's a scroll-driven unboxing of a placeholder "Example Kit" (no real kit design/photos exist yet — box, components, and copy are all stand-ins meant to be swapped for real assets later). Scene contents (box/lid/components/particles/lighting/postprocessing/HUD callouts) live in `src/components/kitExperience/Scene.jsx`; chapter boundaries, copy, and callout data live in `src/components/kitExperience/content.js`.

- **Single source of truth is a scroll progress number (0–1).** A tall spacer div (`TOTAL_VH` in `content.js`, currently 750vh) drives a GSAP `ScrollTrigger` (`scrub: true`, no `pin`) whose `onUpdate` writes into a plain ref (`progressRef`, not React state) so the 3D scene can read it every frame inside `useFrame` without triggering re-renders. Everything — camera path, box/lid rotation, which component is risen, HUD callout opacity — is a pure function of that one number via chapter ranges defined in `CH` (`content.js`). This is what makes the timeline scrub perfectly in both directions.
- **The canvas is `position: fixed` via a React portal to `document.body`**, not GSAP's `pin` feature. This is deliberate: `PageTransition` (wraps every page) is a Framer Motion `motion.div` that leaves a persistent inline `transform` on itself even at rest, and any `transform` on an ancestor breaks `position: fixed` (creates a new containing block). Portaling straight to `document.body` sidesteps that entirely. Visibility of the fixed layer is toggled via a `self.isActive` React state (from ScrollTrigger's `onToggle`), not by mounting/unmounting the `<Canvas>` — so scrolling in/out of the section doesn't tear down the WebGL context.
- **Camera/box motion must stay monotonic, not oscillating, within a chapter.** An earlier version used `sin()`-based vertical bobbing on the camera for "cinematic drift" — this reads as visible shake once tied 1:1 to raw scroll input (trackpad/wheel deltas are noisy). There's also a `smoothedP` ref inside `Scene.jsx` that low-pass-filters the raw progress before it drives anything, specifically to damp out scroll-input jitter. If motion ever feels shaky again, suspect (a) newly-added oscillating terms in `updateCamera()`, or (b) the smoothing damp factor (`delta * 6`) needing to be lower.
- **The "Example Kit" title is real 3D geometry** (drei's `<Text>`), not an HTML overlay — it sits behind the box in world space so the box's own depth buffer occludes it naturally (no manual raycasting needed, unlike the HUD callouts below). An earlier attempt used drei's `<Html occlude>` for this and it back fired: occlusion is a single raycast to the anchor point, and since the anchor was dead-center behind the box, it was permanently invisible.
- **HUD callouts** (packaging details, per-component labels) are drei `<Html>` elements anchored to 3D positions, with opacity/transform driven imperatively via direct ref/style mutation inside `useFrame` (not React state) to avoid re-render churn on every scroll tick.
- Falls back to a simpler static layout (no pin, no postprocessing, `quality="low"`) on mobile (`useMobile` hook) and when `prefers-reduced-motion` is set.
